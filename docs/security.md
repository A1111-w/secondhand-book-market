# 安全基线

## 信任边界

- Web 与微信小程序都是不可信客户端，`userId`、`role`、积分、商品归属和文件名不能由请求体决定。
- JWT 只标识当前用户；管理员 API 必须再次从数据库读取用户角色。
- 联系方式属于受控字段，列表和未解锁详情不能返回真实值。
- 学生证、头像和商品图属于用户上传内容，必须限制 MIME、扩展名、大小和路径。学生证保存在私有卷，通过 `/api/admin/verification-image` 鉴权读取；旧 `/uploads/verify/*` 路径固定返回 404。
- 外部 ISBN、微信和邮件服务都使用服务端环境变量，响应不能泄漏 Secret。

## 上线检查

1. `JWT_SECRET` 至少 32 字节，不能使用代码 fallback；轮换后已有会话全部失效。
2. 数据库账号只授予本 schema 所需权限，不允许远程 root 登录。
3. 生产反向代理设置 TLS、请求体上限、速率限制、访问日志和安全头。
4. `AD_REWARD_ENABLED=false` 保持关闭，直到接入微信服务端可验证的广告回调、事件幂等键和每日上限。
5. 管理员 `/admin` 只使用数据库角色鉴权；小程序不包含管理员代码，不能把“隐藏按钮”当授权控制。
6. 禁止部署 debug、seed 或修复数据 API；维护动作使用受审计脚本或 Prisma migration。
7. 公开上传目录禁止脚本执行，响应使用 `nosniff`；学生证目录不得由 Web Server 直接映射，图片重编码/病毒扫描可放在私有对象存储流水线中。

## 事件处理

- JWT 或微信 Secret 泄露：先轮换，再重启 Web，最后检查异常登录和管理员审核日志。
- 积分异常：关闭奖励开关，按 `PointLog` 对账，冻结异常账号，修复幂等/限额后再开启。
- 上传恶意文件：隔离文件卷、按哈希定位同源上传，禁止直接在生产目录打开样本。
- 联系方式泄露：立即修复列表/详情返回字段，审查访问日志和已解锁记录，并通知受影响用户。
